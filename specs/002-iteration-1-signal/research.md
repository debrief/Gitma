# Research: Iteration 1 — Is the Signal Learnable?

Phase 0 output for [plan.md](plan.md). Each item: decision, rationale, alternatives.

## R1. Training runtime and budget

- **Spike (2026-10-11)**: `@tensorflow/tfjs-node` 4.22.0 installs and runs on the 4-core container
  (oneDNN, AVX-512). At batch 256 and 240 rows: LSTM-64 ≈ 200 windows/s, BiLSTM-64 ≈ 100 windows/s;
  batch 64 is ~3× slower. One 80k-window epoch ≈ 7 min (LSTM), ≈ 13 min (BiLSTM).
- **Decision**: stay on tfjs-node; batch 256; **6-hour wall-clock cap per model** (user decision, first 4 h then 6 h;
  relaxing SRD §4's one hour). Training stops at the earlier of: max epochs, early stopping on
  validation loss (patience 3), or the wall-clock cap. Measured in the run: ≈ 12.6 min per LSTM epoch, so ≈ 28 LSTM epochs fit in 6 h.
- **Alternatives**: one-hour cap with early stopping (≈ 4 BiLSTM epochs, likely undertrained);
  30k-scenario subset (fewer examples); PyTorch port (SRD §8 fallback, more work, breaks the
  single-stack setup). Revisit the PyTorch port if iteration 3's 10^6 scenarios are needed.
- **SRD conflict**: §4 says "a run completes in under an hour"; flagged for an SRD amendment.

## R2. Determinism

- **Spike**: with every initializer given an explicit seed and batches fed via `trainOnBatch` in an
  order from our seeded PRNG, two training runs give byte-identical weights for LSTM and BiLSTM
  (also with `TF_NUM_INTRAOP_THREADS=1`).
- **Decision**: never use `fit({shuffle: true})` or unseeded initializers; derive every initializer
  seed and the epoch shuffle order from the manifest's `train_seed` via SplitMix64. Golden test: two
  2-epoch runs on 64 scenarios must hash identically.
- **Caveat**: identical under the pinned Node and tfjs-node versions on the same CPU family; oneDNN
  may pick different kernels on other CPUs. Cross-machine weight identity is *not* promised
  (constitution II covers stored data; model weights follow the same float32 rule but kernel choice
  can differ). Recorded in the manifest (`cpu_model`).

## R3. Causal convolution

- **Spike**: tfjs `conv1d({padding: 'causal'})` silently behaves as `'valid'` (60 rows → 58 with
  kernel 3), contrary to Keras.
- **Decision**: explicit left padding built from Keras-equivalent layers:
  `Reshape([240, 1, C]) → ZeroPadding2D([[k−1, 0], [0, 0]]) → Reshape([240 + k − 1, C]) → Conv1D(valid)`.
  Causality enforced by the same perturbation test as the LSTM (FR-006).
- **Alternative**: custom layer (not Keras-portable, rejected).

## R4. Architectures (small, Keras-plain; SRD §4)

| Model | Layers | Params (approx.) |
| --- | --- | --- |
| `instantaneous` | Masking → LSTM(96, seq) → TimeDistributed(Dense(4)) | 41k |
| `time_late` | Masking → Bidirectional(LSTM(96, seq)) → TimeDistributed(Dense(4)) | 82k |
| `causal_cnn` (control) | (left-pad → Conv1D(64, k=15, relu)) ×3 → TimeDistributed(Dense(4)) | 130k |
| `mlp` (control) | Flatten(240×10) → Dense(256, relu) → Dense(256, relu) → Dense(240×4) → Reshape | 0.93M |

- Output channels: `log_range_km`, `course_sin`, `course_cos`, `speed_scaled` (feature-layout targets
  0–3). Position is derived, not trained (SRD §4).
- 96 units sits in the SRD's 64–128 range; it's one of ≤ 4 configurations per model (FR-009); the
  others are 64 and 128 units, and one learning-rate variant.
- The causal CNN's receptive field (43 rows, ≈ 7 min) is deliberately shorter than the window, so
  it is a fair "local pattern" control, not a sequence model in disguise. No dilation: tfjs-node 4.22
  has no gradient for dilated `conv2D` (found in implementation), so width comes from k = 15.
- Masking: zeros in padding rows are masked; dropout rows keep `window_mask = 1` (iteration 1 has no
  dropouts anyway).

## R5. Loss

- **Decision**: custom loss over `y_true` packed as `[240, 5]` = 4 targets + loss weight. Weight =
  feature-layout loss mask (rows after the zig) for causal models; = window mask for non-causal
  models (SRD §4 masks only the causal variant to post-zig rows). Per-row loss
  `w_r·(Δlog r)² + w_c·(Δsin² + Δcos²) + w_s·(Δspeed)²`, averaged over weighted rows. Default
  `w_r = 1, w_c = 1, w_s = 1` (all terms O(0.1–1) after scaling).
- **Note**: non-causal models trained on all window rows are still *scored* only from `zig_index + 1`
  onward, like every estimator, so the comparison is like-for-like.

## R6. Data loading

- **Decision**: read `.features.bin` with random access by scenario (offsets are fixed-size per
  scenario after the header) and assemble each batch in memory; one epoch = one seeded permutation.
  Train features for 8×10^4 scenarios ≈ 1.3 GB on disk, never loaded whole (FR-002). Validation
  split loaded whole (10^4 ≈ 160 MB).
- Feature files are generated by `tma-features` from iteration 0, unchanged.

## R7. Model → prediction

- Per-timestep rows from `zig_index + 1` to the end (same rows as the classical solver):
  range `= 1000·exp(log_range_km)`, course `= atan2(sin, cos)`, speed `= speed_scaled ·
  speed_scale_mps`, position from range and the last valid bearing (as the naive baseline).
- Non-finite outputs → row with `converged = false` (counts as gross).
- Estimator names: `lstm-instantaneous`, `bilstm-time-late`, `cnn-causal-control`, `mlp-control`,
  and `<name>-shuffled` for the leakage run.

## R8. G1 and checks

- G1 point: `zig+300s`, slice `overall`, metric `range_rel_median`; pass iff each recurrent variant
  < 0.5 × naive (per-timestep naive, same scenarios).
- Consistency: for each curve point (60 s steps), time-late median range error ≤ 1.05 × instantaneous.
- Controls: each recurrent model must have lower median range error than its control at `zig+300s`
  and `final`.
- Leakage: shuffled-label instantaneous model median within ±10% of naive at `zig+300s`.
- Checks other than G1 itself are recorded as separate `GateCheck`s; the verdict is `pass` only if
  all pass, and the detail lets the team see which failed.

## R9. Results review and PR previews

- **Decision**: results review is a site page (React component in Docusaurus) that reads the
  experiment's `metrics.json`/`curves.csv` at build time and draws curves with plain SVG (no chart
  library). PR previews: a workflow builds the site with `SITE_BASE_URL=/Gitma/pr/<N>/` and publishes
  to `gh-pages/pr/<N>/` (`keep_files`), comments the link, and a close-event workflow deletes the
  folder. Same-repo PRs only (forks have no write token).
- **Alternative**: separate `packages/demos` app (more build machinery; deferred until a demo needs
  in-browser TF.js inference).
